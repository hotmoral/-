# ReadingFlow 글 제작 — 30편 시범 원고 작업 중단 및 이후 우선순위

결정일: 2026-11-22. 사용자 직접 지시. 현재 브랜치: `feature/author-attribute-rng-audit-20261119`.

## 현재 작업 범위

- **기존 시범 30편·90문항에 대한 추가 AI 편집·수정·반복 정밀검수 작업을 중단한다.** R6.9-C 이후 후속 5편씩 편집 계획은 **실행 대상에서 제외**한다.
- 30편 관련 원본·개정 후보·감사 기록·HTML 검수본·관리자 키는 **기록으로 보존**한다. 기존 시범 원고를 새로 승인하거나 파기·병합하지 않는다.
- 30편을 *참고 데이터·자동 테스트 기준선*으로 읽는 것은 허용하지만, **본문/문항을 다시 고치는 것은 새 사용자 지시가 있을 때만** 한다.
- 과거 로드맵의 R1-A/R6.9 '남은 시범 30편 편집' 항목은 **당시 이력**이며, 향후 제작 세션의 할 일이 아니다.
- 정답·원고·문항·훈련 파생 데이터의 원본 버전 보호 원칙은 계속 유효하다.

## 남은 실제 제작 업무 (우선순위)

1. **신규 제작 QA의 실행 연결:** `NEW_PASSAGE_AUTHORING_AND_MCQ_CANONICAL_2026-11-22.md`와 17개 문항·원고 검수 항목을 실제 생성 입출력·기록/보류 흐름에 연결한다. 구조 검사와 의미·사실·문장 검수의 서로 다른 판정 능력을 구별한다. 배경지식으로 지문 없이 맞힐 수 있다는 이유는 불합격 사유가 아니다.
2. **주제 자동 선정:** 18대분야·298세부분야 확장 가능한 분류안을 바탕으로 대분야→세부 분야→주제→핵심 질문을 선정/기록하고, 최근 원고의 소재뿐 아니라 전개·추론·독해 목표 중복을 점검한다. 분류안의 사용자 최종 승인·자동 편성은 별도로 구분.
3. **필자 24속성 시스템 검증:** 현행 172후보에서 속성별 독립 균등 추첨을 유지하고, 실제 원고에서 속성 발현·자연스러움·논증/난도/사실 훼손을 블라인드 비교한다. 미승인 후보 12개를 자동 채택하지 않는다.
4. **신규 지문 자동 생성 종단 통합:** 주제·독해 목표·검증 사실·필자→원고→발문·정답/오답 3개→정답 유일성/근거→반복·문체·비문 검사→수정 후보/보류/승인을 단일 실행 계약으로 연결한다. 처음에는 **새 시범 원고 1편**으로 검증하고 통과 시 단계적 확장.
5. **훈련용 파생 데이터와 버전 계약:** 동일 원문에서 ③ 어휘, ④ 어구/문장 순간 제시, ⑤ 의미 덩어리 A/B, 나머지 훈련에 필요한 데이터만 파생. Unicode 오프셋·원문 해시·STALE 처리 및 원문 수정 시 종속 데이터 재검증.
6. **소규모 생산 파일럿과 실측:** 새 지문으로 실제 문체 다양성·사실 오류·복수 답·비문·오답의 지문 관련성·원고 중복·원고당 비용 등을 평가하고, 독립 사람 검수 및 실제 학습자 타당화는 별도 시행한다.
7. **개발 세션과 연동:** 승인된 신규 콘텐츠가 10훈련/8슬롯 개인화·노출 이력·회차별 평가 신규성·웹앱/Android APK 저장 구조에 정확하게 연결되는지 후속 개발 세션에서 검증한다.

## 시행 경계

- 글 제작 세션은 **원고 생성/자동검수/파생 콘텐츠**를 우선 맡고, 훈련 엔진/개인화/웹앱/APK 구현은 개발 세션의 담당 영역이다.
- 외부 원문 100편 확보/이용권 검토와 자체 창작 원고 생산은 **별도 작업**이다.
- GitHub Actions 실패 원인은 별도 CI 보수 과제이다. 문서·검사 코드 파일을 추가했다는 사실만으로 테스트 통과를 주장하지 않는다.
- 본 업무 전환은 **30편의 최종 승인·검증 완료 판정이 아니다**. 현재까지 독립 검수/실학습자 승인 기록은 확보되지 않았다.

**다음 착수:** 기존 17개 검수 체크리스트를 신규 원고 생성 실행 단계의 입출력 및 품질 보류 게이트에 연결한다. 기존 30편을 고치는 작업은 시작하지 않는다.
