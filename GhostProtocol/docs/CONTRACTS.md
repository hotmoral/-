# 정식 의뢰 시스템 v0.22
12개 검증 및 ZERO 등록 승인 → ECHO 인계 → 의뢰 목록 → 수락 → 브리핑 → 최초 LUNA 분석(1회) → 접속 → 결과 → 목록.
세 개 의뢰를 동시에 제시 (개수는 이번 구현 기본값). 기존 12종 임무 및 생성 엔진 활용. 유형 중복 방지. 생성된 네트워크 스냅샷을 저장하여 표시된 제한시간/최고 퍼즐 난도/설비 위험도/추적 시작 조건과 실행본 일치. 위험도는 설비 플래그 기준이며 추적 개시 조건과 별도. 수락 취소는 접속 전 가능. 성공/실패 기록 후 해당 항목만 새로 보충하고 다른 항목 유지. 선택·수락한 의뢰는 재실행 시 복구(임무 중간 상태는 저장하지 않고 같은 네트워크로 다시 시작). 입문 선택은 검수용으로 유지, 정식 등록 후에는 기존 드롭다운 잠금. 초기화/전체화면은 목록에서도 가능.
보수 CR은 임시 견적이며 실제 계좌·지급·차감·평판은 미구현. 견적 산식: 500 + 전체 작업 수×90 + 생성 단계×200 + 설비 위험 가산(높음 400, 보통 150, 낮음 0)을 100 단위 반올림. 최종 수치/화폐/갱신 정책은 사용자 승인 전 미확정. 현 구현의 수락·교체 정책 역시 초기 검수용이며 후속 갱신 체계 논의에서 확정한다.
자동 검수: Chromium 768×358, 692×313, 640×300, 시험 통과/등록/인계/목록/수락/취소/재로드/최초 LUNA/성공/실패/목록 보충, 카드 넘침 없음, JS 오류 없음. 모의 localStorage 및 목표 상태 주입 사용. 실제 스마트폰 미검수. 25개 퍼즐 데이터 및 기존 임무 정의/transition 함수 변경 없음.

## v0.23 생성·갱신 개선
기존 v0.22의 3개 선택, 수락 취소 및 성공/실패 후 해당 의뢰만 자동 보충 유지. 수동 리롤이나 시간 만료 갱신은 도입하지 않음(정책 미확정). 발행 이력 48개를 저장하고 과거 완료/기존 목록에서 가능한 이력을 복원. 최근 24개에서 출현 횟수가 적고 오래 등장하지 않은 유형 우선. 동일 목록에서 유형 및 ID 중복 방지. 기존 2개가 같은 위험군이면 다른 위험군 우선 보충(임무 프로필 위험 플래그 기준). 네트워크 유효 후보 최대 8개 비교, 최근 12개 토폴로지와 현재 보드 토폴로지/최고 퍼즐 난도 중복에 점수 페널티. 동일 구조 지문(설비 유형/작업 ID·난도/플래그/연계·간선/목표) 최근 48개 및 현 목록에서 제외. 난도 자체 및 보수 산식은 v0.22 그대로, 다양성은 가능한 후보 범위에서만 우선. 잘못된 저장 목록 항목 제외 및 보충. 승인된 의뢰 스냅샷 불변.
검수: 순환/무작위 선택 각각 생성 단계 1·2에서 300회씩 총 1200회 갱신; 각 실행에서 신규 네트워크 지문 중복 없음, 목록 3개 유효/유형·ID 중복 없음, 미선택 의뢰 불변, 저장 이력 48개 제한. 무작위 선택 실행의 유형별 발행 횟수 23~29회(단계1), 23~28회(단계2), 각 302개 관측. 순환 선택 한 실행은 위험군 혼합 강제에 따라 유형별 12~50회 편차 발생; 선택 패턴에 따른 편중을 완전히 제거하지는 않음. 보수/잔액/평판 미구현.

## v0.24 정책 변경
v0.22~23의 보수 견적은 성공 시 누적 수익 기록으로 확정 지급하되 소비 기능은 없다. 경제/장비 구매 계획은 폐기. 실패는 신뢰도 감소만 적용. 보상·해커 성장 기준은 CAREER.md. 신규 단계2 의뢰는 D 이상 및 기존 숙련 조건 충족 필요(기존 발행/수락 의뢰 불변).

일반 의뢰 신규 발행은 F 6종/E 9종/D 이상 12종(CAREER.md). 기존 목록 유지, 후보 부족 시 위험군 혼합 선호만 완화. 특수 의뢰는 일반 목록과 별도 패널, CIPHER의 비공개 통신으로 제공.
