## 피드백 및 확정 디자인
R1: 기준 비트열과 비교 관계가 직관적이지 않고 전문 용어/배치/설명이 어렵다는 사용자 지적.
R2: 기준 줄 강조 및 화살표, 쉬운 숫자 표현 적용. 사용자 지적: 화살표 의미 불명확, 대형 칸의 풍선 같은 여백, 해킹 분위기 약화. 전문 용어는 화면의 요소를 직접 가리키며 간결하게 설명하는 방향으로 재확정.
R3: 세로 채널형 제안 적용 시도. 실제 기기에서 별도 겹친 테두리와 번호/숫자/체크 위치 불일치, 패널 상하 경계 불일치, 설명의 대사와 조작 결과 불일치 지적. R3 폐기.
R4: 각 열을 독립된 실제 레이아웃 요소로 구성, 열 번호/기준 비트/연결/검사 비트를 동일한 좌표 체계에 배치. 각진 데이터 칸, 크기 상한, 중앙 정렬, 체크와 주황 강조 영역 분리, 좌우 상하 경계 일치. 비교 시연에서 이전 분석 결과 초기화. 사용자 최종 승인: 2026-11-26 14:37 UTC. 독립 파일 archive/Ghost_Protocol_Bit_Inspection_R4.html (blob 36fb5ec8db0da44efddccfee0ad9998a45033f76).

## 최종 CIPHER 설명 (실제 R4 소스)
1. 데이터에 오류가 발생했어. 기준 비트열과 비교해서 오류 비트를 찾아내야 해.
2. 맨 위 파란색 줄이 기준 비트열이야. 같은 세로줄의 비트끼리 비교해.
3. 기준은 1인데 아래는 0이야. 이렇게 일치하지 않는 비트를 선택해.
4. 기준과 일치하는 비트는 정상이야. 선택하면 오선택으로 기록돼.
5. 오류 비트를 모두 찾아내면 검출이 완료돼.
기준 비트열/오류 비트/일치하지 않는 비트 강조. 2단계 비교할 정상 비트 및 해당 채널 강조, 3단계 첫 불일치(1행 3열) 비교·선택, 4단계 정상 비트 비교·오선택, 5단계 남은 오류(2행 6열) 선택·완료. 예시 기준 10110010. 시연 4초 대사 선행, 1.7초 비교 강조 후 선택(2단계는 1.5초 비교 시연만), 520ms 분석, 결과 유지. 대사 자동 전환 없음. 시연 상태와 실전 분리, 이전/재생 시 예약 취소.
