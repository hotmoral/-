# 논리 퍼즐 개발 공통 기준 — v1.4 (2026-11-26, 통합본 v0.50)
## 0. 문서 지위와 작업 시작 전 필수 확인
이 문서는 v0.35~v0.45 및 독립 AUTH LAB 사용자 피드백에서 확정된 공통 설계·시연·연출·검수 원칙을 한곳에 모은 현재 우선 적용 기준이다. 후속 작업자는 새 퍼즐의 제안, 구현, 수정, 통합에 앞서 반드시 이 문서와 최신 ROADMAP.md, 대상 퍼즐의 실제 최신 실행 소스를 읽는다. 동일한 사항을 사용자에게 재확인하거나 다시 지적받지 않도록 적용한다.
충돌 시 최신 사용자 명시 결정 > 이 공통 기준의 최신 승인 사항 > 해당 퍼즐별 최종 승인 명세 > 기존 일반 설계 기준 순으로 해석하되, 변경 권한이 없는 규칙은 임의 수정하지 않는다. 이전 버전 기록, 폐기된 시안 및 미확정 후보는 역사 자료로만 사용한다. 게임 전체 정책은 DESIGN.md, CHARACTERS.md, DIALOGUE_STYLE.md, DIFFICULTY.md, CAREER.md, TRACE_AND_SPECIAL_CASES.md 등 해당 분야 최신 기록을 따른다. 용어 후보는 TERMINOLOGY_STANDARD.md 참고하되 일괄 승인된 것으로 간주하지 않는다.
현재 통합 실행본 Ghost_Protocol_Integrated_Lab_v50.html. 활성 퍼즐 24종, 인증 코드 추론 내부 ID10 영구 폐기, 인증 코드 탐색 ID11 정식 채택. 기존 나머지 내부 ID는 유지하고 표시 번호만 연속 01~24. 개선 통합 3/24종: 인증 코드 탐색(ID11), 이상 탐지(ID01), 일치 검증(ID02). 인증은 AUTH_INTEGRATION_V40.md 및 AUTH_POPUP_V41.md의 v0.48까지, 이상 탐지는 ANOMALY_SCAN_V49.md 및 SCANNER_MATCH_V50.md를 참조.

## 1. 세계관과 게임성 [필수]
- GHOST PROTOCOL은 가상 네트워크 및 독립 논리 퍼즐 기반 게임이다. 실제 외부 시스템 접속·침투가 아닌 로컬 시뮬레이션.
- 목표는 '해킹 테마를 씌운 문제집'이 아니라 보안 작업을 수행하는 과정에서 논리적 판단이 필요한 게임. 각 퍼즐에 실제 게임 내 설비의 역할, 작업 목적, 가상 도구의 기능, 조작 결과가 설비에 미치는 영향을 연결한다.
- 최초 설명의 도입은 작업이 필요한 이유 → 제공된 도구(예: CIPHER가 준비한 보안 인증 단말기) → 도구가 해 주는 일 → 사용법 순으로 자연스럽게 연결. 결과를 왜 얻을 수 있는지 설명하지 않고 갑자기 숫자나 단서를 제공하지 않는다. 도구가 정답을 직접 알려 주지는 않는다. 도구 설정은 게임 내 가상 기능으로 한정한다.
- 퍼즐별 기술적 정체성을 살린다. 예: 탐지/대조=데이터 스캐너, 인증=보안 인증 단말기, 복구=손상 데이터 분석/복구기, 설정=제어 콘솔, 경로=네트워크 관제, 회로=회로 기판, 분류=패킷 처리. 이는 디자인 모티브 예시이며 세부 도구 명칭과 규칙은 해당 퍼즐 검토·승인 후 확정.
- 규칙/목적/설비가 중복된 유형은 독립 제작 전 중복성을 검토한다. 통합/폐기는 사용자 승인 필요. 인증 추론 폐기는 이미 승인됨. 단순히 숫자만 바꾼 동일 작업을 별도 퍼즐로 양산하지 않는다.

## 2. 화면과 조작 디자인 [필수]
- 모든 디자인 제안·시안·실행본·검수의 기준은 모바일 가로형. 채팅 표시 편의 때문에 세로 시안을 제시하지 않는다. 가로 실제 가용 영역(브라우저 주소창, 안전 여백, 임무 HUD 및 팝업 내부 포함)을 기준으로 설계. 세로는 필요할 때 보조 호환만 확인하며 기본 방향을 바꾸지 않는다.
- 대표 검수 뷰포트 844×390, 768×358, 692×313, 640×300 CSS px. 독립 실행본뿐 아니라 통합본과 실제 팝업 내부 iframe 가용 영역에서도 검수한다. 필요 시 사용자 기기 크기에 추가 대응.
- 공통 팔레트/선형 아이콘/글꼴/터미널 스타일 유지. 절제된 산업용 디지털 인터페이스, 청록/어두운 배경, 정보에 의미 있는 기술 모티브. 무의미한 영문 코드, 장식용 그래프, 과한 네온/글리치, 불필요한 문구·버튼 금지. 글리치는 기존처럼 수평 신호 왜곡 중심.
- 실제 플레이 레이아웃은 퍼즐 고유의 조작·정보량·시선 흐름을 기준으로 독립 설계. 화면을 채우려고 좌우 강제 분할하거나 버튼/카드를 과도하게 늘리지 않는다. 인증 탐색의 좌측 조작·우측 기록 배치는 그 퍼즐의 승인 디자인이지 전 퍼즐의 강제 양식이 아니다. 정사각형 작업판도 필요하면 가로 화면 안에서 유지.
- 글보다 기호, 색상, 도형, 연결선, 움직임으로 의미를 표현할 수 있으면 시각화 우선. 색만으로 구분하지 않고 형태나 텍스트 병행. 고정 SVG 아이콘을 공용 사용하여 글꼴/기기별 기호 변형 방지. 의미·조작 가능 상태·정답 단서 혼동 금지. 반복적인 상태=기호+색, 수량=기호+숫자, 핵심 목적/필수 제약=명확한 한국어.
- 범례는 관련 데이터 상단 등 읽기 전에 보이는 위치에 고정, 기록 추가로 밀리지 않게 한다. 새 데이터/최신 기록이 중요한 작업은 최신 방향을 명시하고 새 행에 즉시 알아볼 수 있는 라벨·테두리/색·짧은 수신 효과를 적용. 인증 탐색은 최신순 상단 고정 및 최신/성공 표시 확정.
- 터치/드래그가 직관적인 유형은 기존 연속 드래그와 되돌리기 등을 유지. 탭으로 강제 변경하지 않는다. 재렌더링 중 터치 캡처, 이동/취소 정리, 스크롤 충돌·연속 조작 검증. 17/20 경로 드래그 및 지도 자동 줌·이동 보간(650ms, 수동 조작 우선)은 v0.36 승인 구현을 보존.
- 작은 화면에서 버튼/기호/숫자가 잘리거나 겹치지 않도록 요소 크기·여백을 조정하되 가독성과 터치 목표를 희생하지 않는다. 한글 어절 중간 분리 금지. 정보가 늘어나는 어려움 난도까지 확인.

## 3. 최초 설명 공통 레이아웃과 진입 [필수]
- 설비 작업 선택 → 기존 공통 CIPHER 설명 팝업 → 사용자의 '문제 시작' → 실제 전체화면 작업 → 완료 및 기존 네트워크 복귀. 설명 모드가 전체화면 실제 게임처럼 진입하거나 자동으로 실전을 시작하면 안 된다.
- 공통 팝업의 기존 가로 규격: 폭 min(69vw,660px), 높이 90dvh 및 기존 최대 높이 제한. 상단 NPC 초상화·퍼즐명·시간 정지, 좌측 해결 방법(현재 단계 NPC 대사), 우측 문제 예시(실제 UI 기반 시연 및 단계 이동), 전체 하단 기존 취소/문제 시작 버튼. 다른 설비 설명과 외곽 배치·크기 통일.
- 예시는 실제 게임과 동일한 요소·위치 관계·조작·반응 순서로 제작하고 공용 렌더러/컴포넌트 사용을 우선한다. 팝업 내부의 정확한 픽셀 크기나 패널 비율을 실제 플레이와 강제로 동일하게 맞출 필요는 없다(v0.42 사용자 승인). 여백·보조 영문·중복 제목·범례 길이 등을 줄여 오른쪽에 맞춘다. 인증의 실전 43:57과 팝업 40:60은 해당 퍼즐의 예시이지 공통 비율 아님.
- 단계 이동의 공통 배치(v0.48~): 우측 예시 제목과 같은 줄 오른쪽에 '다시 보기', 예시 하단에 동일 폭 '이전' / 중앙 현재 단계·전체 단계(예: 2/5) / 동일 폭 '다음'. 페이지 표시를 다시 보기와 다음 사이에 끼워 넣지 않는다. 버튼 비활성 상태에서도 폭과 중앙축을 유지한다. 최초 안내와 도움말 모두 같은 배치. 기존 미개선 퍼즐에는 각 개선 시 적용한다. 마지막 단계가 끝나도 설명 유지. 문제 시작은 명시적 사용자 입력만. 기존 취소/건너뛰기 경로를 유지. 도움말에서 같은 시연을 다시 볼 수 있게 하고, 최초 안내 기록 및 재진입 정책 유지.
- 설명 중 임무 시간과 추적률 정지. 설명용 정답·입력·기록·완료 상태는 실제 생성 문제와 분리. 설명 수행으로 권한·성장·숙련도·오류·보상·임무 결과가 변경되면 안 된다. 예시용 공개 코드/정답/규칙 표시가 실전으로 유출되지 않게 한다.

## 4. 단계별 설명 및 시연 제작 [필수]
- 첫 단계에 상황/목적/도구 및 기능을 소개. 이후 조작 → 시스템 반응 → 결과 수신 → 의미 해석의 인과 순서. 기호 설명을 하기 전 실제로 결과가 생기는 시범을 먼저 보여 준다.
- 한 단계 한 가지 핵심 개념. 기존 안내와 시각적 예시의 의미 중복 제거. 실제 조작 버튼이 눌리는 모습(강조, 입력 값 변화, 드래그 경로 등)을 보여 주고 그 결과로 스캔·분석·복구·연결 효과 및 결과가 발생하게 한다. 조작 없이 결과를 미리 생성해 놓고 설명하지 않는다(이전 단계에서 이미 생성된 기록을 그대로 이어 보여 주는 것은 허용).
- 단계 내부의 동작만 자동 재생. 단계와 대사는 자동 전환 금지. 대사는 시연 시작 전에 충분히 읽을 수 있게 먼저 보여 주고, 시연 중 및 완료 후에도 같은 문구를 계속 표시. 읽어야 하는 두 문장이 서로 교체되어 놓치는 경우 별도 단계로 분리.
- 시연 중 다음 버튼 비활성화, 결과 표시와 충분한 인지 시간이 지난 후 활성화. 이전/다시 보기/취소/문제 시작 시 예약된 동작과 애니메이션을 무효화하여 이전 단계의 효과가 남지 않도록 한다. 이전 단계 재현 및 반복 재생 가능, 결과 상태 무기한 유지.
- 애니메이션은 실제 작업과 동일한 기능/순서/속도를 기본으로 사용한다. 단, 설명용 독해 여유와 단계 분리는 추가 가능. 실제 조작을 불필요하게 느리게 만들지 않는다. 별도 재생 속도 설정은 현재 도입하지 않음. 감소 모션 선호 존중.
- 단계 수는 내용에 맞게 결정. 인증 9단계나 7.74초를 모든 퍼즐에 강제하지 않는다. 인증의 승인 시간 예시는 대사 선행 4초 → 숫자 조작 1.5초 → 검사 버튼 강조 0.8초 → 실제 스캔 0.44초 → 결과 강조 1초. 긴 안내는 사용자 읽기 시간 고려.
- 마지막 단계는 해결 상태 및 작업의 의미가 명확하게 드러나는 완료 연출. 검사 결과 확인과 완료 안내/연출을 별도 단계로 나누는 것이 필요하면 분리한다. 완료 문구는 연출 뒤에도 유지.

## 5. 실제 플레이 반응과 성공 연출 [필수]
- 조작에 의미 있는 즉시 피드백을 준다. 작업 성격에 따라 스캔·데이터 수신·신호 흐름·회로 점등·복구·검증 등. 장식 자체보다 실제 상태 변화와 인과관계가 보이게 설계.
- 성공은 텍스트만 읽어야 알 수 있는 약한 상태 변화로 끝내지 않는다. 필요시 중앙 오버레이/명확한 아이콘 상태 변화/색상 확산·완료 메시지 및 완료 후 지속 표시. 실제 작업과 설명 시연에서 같은 연출 사용. 물리적 대상(자물쇠 등)의 구조와 동작은 현실적으로 표현.
- 공통 완료와 모듈 자체 완료 연출의 중복 금지. 임무 타이머/추적/오류/중단/권한 연동은 기존 정책 유지. 완료 이벤트 정확히 한 번, 연출 종료 후 기존 흐름에 맞게 권한 부여 및 복귀. 실패/일반 검사 결과를 성공으로 오인하지 않게 한다.
- 단순 불일치/검사 결과 자체와 실제 작업 오류(규칙 위반 등)를 구별한다. 예: 인증 코드 탐색의 실패 검사 및 빨간 X 수량은 오류/추적 벌점이 아니다. 다른 퍼즐의 오류 정책은 기존 규칙 대조 후 유지.

## v0.46 추가 확정 — 캐릭터 이미지와 대사 및 논리 흐름의 일치
사용자 지적 및 승인(2026-11-26): CIPHER는 검은 후드·청록 파형 가면을 쓴 신원 불명의 노련한 해커이자 선발 담당자다. 대사는 침착하고 절제된 자연스러운 반말, 능숙한 시범 및 판단을 유도하는 태도로 성격을 드러낸다. 특정 어미(-지/-군)를 의도적으로 반복하거나 '검사해 보지' 같은 국어책식 표현, 지나치게 친근한 교사 말투, 감탄사 남발을 피한다. 기존 캐릭터별 말투와 역할은 보존하되 초상화의 인상·성격·상황과 함께 검수한다.
단계 간 내용 검수: 말투 교정만 하지 말고 앞 단계의 정보가 다음 행동의 이유가 되는지 확인한다. 규칙 설명 후 실제 탐색으로 전환하는 멘트, 단서가 알려 주는 정보와 알려 주지 않는 정보의 구별, 일부 입력만 변경해 결과를 비교하는 탐색 원리를 명시한다. 아직 검사하지 않은 결과를 이미 얻은 것처럼 말하지 않는다(시연 전에 조건형/예고형, 결과 확인 단계에 완료형). 예시에서 특정 정답을 시험해 보는 것과 단서로 정답을 확정한 것을 구별한다. 실제 플레이 정답 유출 금지. 확정된 설명 목적을 말투 수정 과정에서 삭제하지 않는다. 모든 퍼즐의 신규 대사는 전체 단계 연속 낭독 및 화면 가독성 검사로 검수한다.

- 스캔과 표식처럼 하나의 동작에서 비롯되는 효과는 동일한 진행값/좌표로 연결한다. 스캔선이 해당 칸을 지나는 위치와 테두리 생성 위치·속도가 일치해야 한다. 무관한 타이머로 순서만 흉내 내거나, 선이 지나기 전 테두리가 나타나는 연출 금지. 감소 모션과 화면 크기 변경·취소 시 예약 효과 정리도 확인.
- 완료 표시는 읽고 성취감을 느낄 수 있는 시간 확보. 이상 탐지 전용: 최종 탐지 1.8초 → 스캔 1.6초 → 완료 표시 1.5초(기존 0.6초를 사용자 승인으로 확대) → 네트워크 복귀. 총 약 4.9초, 연출 종료 신호로 복귀하며 중복 공통 팝업 금지. 인증의 별도 6초 구성 보존. 공통 수치로 강제하지 않는다.
